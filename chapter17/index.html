    Chapter 17. 여러 모델 비교하기 - 누가 더 똑똑한가?¶

    🎯 이 장에서 배우는 것¶

    • 여러 머신러닝 모델을 Orange3에서 동시에 비교할 수 있다
    • 혼동 행렬(Confusion Matrix)을 읽고 모델의 강점과 약점을 분석할 수 있다
    • 과적합(Overfitting) 현상을 이해하고 식별할 수 있다
    • 정확도, 정밀도, 재현율의 의미를 구분할 수 있다

    💡 왜 이걸 배우나요?¶

    같은 문제를 여러 학생이 풀면 답은 같지만 풀이 과정은 다릅니다. 의사결정나무는 "이 특징을 먼저 본다"는 전략을, kNN은 "주변 이웃들을 보자"는 전략을, 로지스틱 회귀는 "확률로 경계선을 그어보자"는 전략을 씁니다.

    그렇다면 우리 데이터에는 어떤 전략이 최고일까요? 이 장에서는 여러 모델을 한 무대에 올려놓고 누가 진짜 똑똑한지 비교합니다.

    하지만 주의할 점이 있어요. "시험 족보를 외워서 만점을 받은 학생"은 그 시험에만 좋은 성적을 보이고, 새로운 문제는 못 풉니다. 모델도 마찬가지예요. 이것이 과적합이라는 함정입니다. 우리는 이것도 함께 배우겠습니다.

    📚 핵심 개념¶

    개념 1: Test and Score 위젯으로 모델 비교하기¶

    비유: 같은 시험지로 여러 학생의 실력을 한 번에 비교하는 것처럼, Test and Score 위젯은 같은 데이터로 여러 모델의 성능을 동시에 평가합니다.

    정의: Test and Score는 Orange3의 평가 도구로, 여러 개의 학습 모델(Learner)을 받아서 같은 테스트 데이터에 대해 각각의 성능을 계산하고 비교해줍니다.

    핵심 이해: - 입력: 데이터 위젯, 여러 개의 학습 모델 위젯 - 출력: 정확도, 정밀도, 재현율 등 성능 지표 테이블 - 작동원리: 데이터를 훈련/테스트로 나누고, 각 모델을 훈련한 후 테스트 데이터에서의 성능을 측정합니다

    [데이터] ──┬→ [의사결정나무]
          ├→ [kNN]          ┐
          └→ [로지스틱회귀] →[Test and Score]→ [성능 비교표]

    개념 2: 혼동 행렬(Confusion Matrix) 읽기¶

    비유: 의사가 환자를 진단할 때, "정말 병이 맞는 환자를 맞게 진단했나?", "건강한 사람을 건강하다고 했나?", "틀린 진단은 어떤 종류인가?"를 보는 표입니다.

    정의: 혼동 행렬은 분류 모델의 예측 결과를 4가지 경우로 나눈 표입니다.

    예측값\실제값    긍정(Yes)      부정(No)
─────────────────────────────────────
긍정(Yes)      참 긍정(TP)    거짓 긍정(FP)
부정(No)       거짓 부정(FN)   참 부정(TN)

    4가지 경우 이해하기:

    • TP (True Positive): "병이 있어" → 맞게 진단 ✓
    • TN (True Negative): "건강해" → 맞게 진단 ✓
    • FP (False Positive): "병이 있어" → 실제로는 건강함 ✗ (과잉진단)
    • FN (False Negative): "건강해" → 실제로는 병이 있음 ✗ (오진)

    실전 예시: 아이리스 데이터에서 "Setosa인지 아닌지" 분류한다면: - TP: "Setosa야" → 정말 Setosa (맞음) - FP: "Setosa야" → 실제론 Versicolor (틀림, 거짓경보) - FN: "Setosa 아니야" → 실제론 Setosa (놓침, 중요한 실수)

    개념 3: 정확도, 정밀도, 재현율¶

    이 세 가지 지표는 다른 질문에 답합니다:

    정확도 (Accuracy) - 질문: "전체 예측 중 몇 개가 맞았나?" - 식: (TP + TN) / (전체) × 100% - 언제 쓸까: 모든 클래스가 균형있을 때

    정밀도 (Precision) - 질문: "우리가 '긍정'이라고 말한 것 중 정말 맞는 게 몇 개인가?" - 식: TP / (TP + FP) × 100% - 언제 쓸까: 거짓 긍정이 치명적일 때 (스팸 필터, 신용카드 사기 탐지)

    재현율 (Recall) - 질문: "실제 긍정인 것들 중 우리가 놓친 게 몇 개인가?" - 식: TP / (TP + FN) × 100% - 언제 쓸까: 거짓 부정이 위험할 때 (암 진단, 보안 위협 탐지)

    구체적 예시: 암 진단 모델 - 정밀도 90%: "암이라고 진단한 100명 중 90명이 정말 암" - 재현율 95%: "실제 암 환자 100명 중 95명을 잡았고, 5명을 놓침"

    개념 4: 과적합(Overfitting)¶

    비유: 학생이 올해 시험 족보만 외워서 만점을 받았어요. 하지만 다음 해 새로운 시험 문제는 못 풀어요. 훈련 데이터에만 과도하게 최적화되어, 새로운 데이터(테스트)에는 성능이 떨어지는 현상입니다.

    정의: 과적합은 모델이 훈련 데이터의 노이즈까지 학습해서, 훈련 정확도는 높지만 테스트 정확도는 낮은 상태입니다.

    신호 잡아내기: - 훈련 정확도: 95% - 테스트 정확도: 65% - 차이가 크다면 → 과적합 의심!

    원인: - 모델이 너무 복잡함 (깊은 결정트리, 작은 k값의 kNN 등) - 훈련 데이터가 너무 적음 - 훈련을 너무 많이 함

    🔨 따라하기¶

    Step 1: 새로운 워크플로우 준비하기¶

    Orange3를 열고 새 프로젝트를 만드세요.

    1. File → New 클릭
    2. 아무 위젯도 아직 놓지 마세요. 깨끗한 캔버스를 유지합니다.

    Step 2: 데이터 로드하기¶

    1. Data 탭에서 File 위젯을 캔버스에 놓으세요
    2. 더블클릭하여 iris.tab 파일을 열기합니다 (또는 다른 분류 데이터)

    Step 3: 여러 모델 준비하기¶

    Learner 탭에서 다음 3개 위젯을 캔버스에 놓으세요:

    1. Tree (의사결정나무)
    2. kNN (k-Nearest Neighbors)
    3. Logistic Regression (로지스틱 회귀)

    각 위젯의 설정은 기본값으로 놓아도 괜찮습니다.

    Step 4: 모델들을 연결하기¶

    File → 각 모델 위젯으로 데이터를 연결합니다:

    [File] ──→ [Tree]
       ├→ [kNN]
       └→ [Logistic Regression]

    Step 5: Test and Score 위젯 추가하고 연결하기¶

    1. Evaluate 탭에서 Test and Score 위젯을 캔버스에 놓으세요
    2. File → Test and Score로 Data 연결
    3. Tree → Test and Score로 Learner 연결
    4. kNN → Test and Score로 Learner 연결
    5. Logistic Regression → Test and Score로 Learner 연결

    최종 구조: 

    [File] ──┬→ [Tree] ──┐
         ├→ [kNN] ────→ [Test and Score]
         └→ [Logistic Regression] ┘

    Step 6: 결과 분석하기¶

    Test and Score 위젯을 더블클릭하면:

    • 상단: 각 모델의 정확도, 정밀도, 재현율 비교 테이블
    • 하단 좌측: 선택한 모델의 혼동 행렬
    • 하단 우측: 모델 선택 탭

    해석해보기: - 어떤 모델의 정확도가 가장 높은가? - 정밀도와 재현율 사이에 차이가 있는가? - 혼동 행렬에서 어떤 클래스를 자주 헷갈리는가?

    📝 전체 코드¶

    Orange3는 비주얼 프로그래밍이므로 전통적인 "코드"가 없습니다. 하지만 Python으로 같은 작업을 한다면:

    from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.neighbors import KNeighborsClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix, accuracy_score, precision_score, recall_score
import pandas as pd

# 데이터 로드
iris = load_iris()
X, y = iris.data, iris.target

# 훈련/테스트 분할
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42
)

# 3개 모델 학습
models = {
    "Decision Tree": DecisionTreeClassifier(random_state=42),
    "kNN (k=5)": KNeighborsClassifier(n_neighbors=5),
    "Logistic Regression": LogisticRegression(max_iter=200)
}

# 각 모델 평가
results = {}
for name, model in models.items():
    model.fit(X_train, y_train)
    y_pred = model.predict(X_test)

    results[name] = {
        "Accuracy": accuracy_score(y_test, y_pred),
        "Precision": precision_score(y_test, y_pred, average='weighted'),
        "Recall": recall_score(y_test, y_pred, average='weighted'),
        "Confusion Matrix": confusion_matrix(y_test, y_pred)
    }

# 결과 출력
for name, metrics in results.items():
    print(f"\n{name}")
    print(f"  Accuracy: {metrics['Accuracy']:.3f}")
    print(f"  Precision: {metrics['Precision']:.3f}")
    print(f"  Recall: {metrics['Recall']:.3f}")

    ⚠️ 자주 하는 실수¶

    실수 1: 혼동 행렬을 거꾸로 읽기¶

    ❌ 틀린 해석: "FP가 많으니까 우리 모델이 자주 틀렸다"

    ✓ 올바른 해석: "FP가 많다 = 부정을 긍정으로 잘못 진단한다 = 거짓경보가 많다"

    → 어떤 종류의 실수를 하는지가 중요합니다!

    실수 2: 정확도만 보고 모델 선택하기¶

    ❌ 틀린 접근: "정확도 92%가 최고니까 이 모델 쓰자"

    ✓ 올바른 접근: "정밀도와 재현율은? 실제 문제에서 뭐가 더 중요한가? 혼동 행렬은?"

    → 예: 암 진단이면 재현율(놓치는 환자 없기)이 정밀도보다 중요합니다!

    실수 3: 훈련 정확도와 테스트 정확도를 구분 못 하기¶

    ❌ 위험한 신호: "모델이 훈련 데이터에서 99%, 테스트에서 65%?"

    ✓ 대처: 과적합입니다! 모델 복잡도를 줄이거나, 더 많은 데이터를 모으세요.

    → Test and Score에서는 자동으로 테스트 정확도만 표시됩니다. 훈련 정확도는 따로 확인해야 해요.

    도전 1: k값 변화에 따른 과적합 관찰하기¶

    kNN의 k값을 바꾸면서 정확도 변화를 관찰하세요:

    • k = 1 (매우 작음) → 과적합 가능성 ↑
    • k = 5 (중간)
    • k = 15 (큼) → 과적합 가능성 ↓

    예상: k가 작을수록 훈련 정확도는 높지만, 테스트 정확도는?

    도전 2: 의사결정나무의 깊이 제한하기¶

    의사결정나무 위젯을 더블클릭하고:

    • Max depth = 3 (얕음) → 단순함
    • Max depth = 10 (깊음) → 복잡함

    각각을 Test and Score에 연결해서 비교하세요. 어느 쪽이 테스트에서 더 잘할까요?
